## Summary

A three-tier decision engine for LaPis's passive memory behaviors:

1. **Native JS engine** (`src/decision/`) — tiny linear models trained in-process on locally logged outcomes. **This is the critical path.**
2. **Existing regex classifiers** — day-0 behavior, unchanged, and the training baseline.
3. **Optional `laya-service/` Python sidecar** (pinned `laya` pkg, token-authed, `127.0.0.1:9110`) — a future third tier. Parallel and deferrable (PR9–PR11).

Everything lands **dark**: behavior is byte-identical until a model is explicitly promoted via `decision-promote`. The flywheel is PR-sliced (PR-1 … PR12) so every merged PR leaves `main` green and behaviorally dark.

**Semantics:** routing = FOUR model questions (`wants_source`, `wants_history`, `wants_navigation`, `is_coding_task`; preflight-worthy := `is_coding_task`). The four *model* questions are non-exclusive — but note the day-0 **regex composite is structurally exclusive** (`isPreflightWorthyPrompt` returns false whenever the other three fire; see PR5). Capture v0 = binary save/no-save (regex keeps assigning type; the model's first live role is **veto-only** — suppress false positives, never create saves). Staleness = SQL rules generate candidates, model is a concordance veto (delete only if rule fired AND P(durable) < 0.30). Ranking = λ-blend with the composite, never a hard gate, and **search-path-only** (see PR6). `decideScore` CUT (no ordinal surface exists).

  CREATE UNIQUE INDEX idx_decision_log_dedupe

Repository `src/platform/storage/repositories/decision.js` (facade over `data-access/decision.js`); **no `withTransaction`** on the gateway path (better-sqlite3's deferred `BEGIN` can raise unretryable `SQLITE_BUSY_SNAPSHOT` on read-then-write upgrades across processes — the single-statement pattern is required, not just convenient). ### PR2a (M) — `src/decision/` pure core

- **`contract.js`** — laya wire format (`{state, questions:{qid:{type:'choice'|'noul', instructions, criteria?}}}` → `answers.{qid}` with probabilities/confidence); **four versioned state builders — the ONLY place truncation happens** so native and laya see identical bytes: `buildCaptureState` (head 300 + '…' + tail 700 + final line), `buildPromptState` (raw prompt serialized with the unified 500-char cap — **model-state only**: regex classifiers keep consuming raw text on both transports through day 0; unifying the classifier input is a behavior change and ships only as part of promotion), `buildMemoryPairState`, `buildStalenessState` (lands with the deferred staleness track — spec'd now so the shape is stable). **Truncation helpers are COPIED into `src/decision/state.js` (frozen, `state_format`-owned) — not imported from `summarizeMemoryContent` (hooks-engine): divergent imports = divergent state bytes.** `state_format` int bumped on any builder change.
- **`features.js`** (pure) — tokenizer: NFKC, lowercase, camelCase/snake/kebab/path splitting (compound + parts), numbers→`<num>`, 40-char cap, CJK/Hangul/Kana runs → char bigrams. **The meta+zone head ships first; hashed lexical features are behind a `feature_spec` flag** enabled only at n ≥ 50k labeled rows — at n ≤ 1,000 with L2, rare-bucket weights decay to ~0 and discrimination comes from zone+meta (the plan's own capacity admission). Hash space fixed at **2^16, signed** — the collision-rate criterion is deleted (at these n the binding constraint is labels, not collisions). Zone features (existing regex hits as booleans); meta features with fixed transforms (trust clamp[0,1], counts log1p-capped, `Number.isFinite` guards). **Age is per-surface:** capture head — no age feature (there is no prior-memory age at capture decision time; it would be dead weight collinear with the composite's 7d recency term); ranking head — age frozen at log time (log-time age IS serve-time age for queries); staleness (deferred) — event time stored on the row, age recomputed at label time.
- **`primitives.js`** (pure) — decideChoice (softmax), decideNoul (sigmoid), gate.
- **`evaluate.js`** — 5-bin equal-mass ECE + bootstrap CI (REPORT ONLY, never a gate), PR-AUC, paired ΔMRR.
- **Runtime compatibility rule:** a loaded model whose `feature_spec`/`state_format` ≠ current builders is **refused at score time** (treated as untrained) — silent feature skew is how this flywheel poisons its own shadow data. Dataset builders filter `decision_log` by current `state_format`.

Tests: determinism (seed hash excludes time-varying fields), pure functions, synthetic convergence.

### PR3 (S/M) — CLI router `src/cli/commands/decision.js`

Single-token commands: `decision-get-model` (returns `{models:{capture:null,…}, shadow:{…}, generated_at}` — nulls for untrained, NEVER errors), `decision-log-batch` (both unadvertised, dashboardRouter pattern — `USAGE = {}` template verified), plus user-facing `decision-status/train/evaluate/promote/demote/log` (paginated, small payloads; no `_wrapAnalysis`). Dispatch is ungated; only session-start filters gate.

**Transport rules (v2.1 — fully plumbed, one path chosen):**
- **Default channel is stdin.** No CLI command reads stdin today and `execFile` (the child transport) has no input option — so `mem()` gains a payload channel: the child path switches to `spawn`/`spawnSync` with piped stdin (`spawnSync(cmd, args, { input })`); the in-process path passes the payload directly. `decision-log-batch` takes the JSON array on stdin.
- **Temp-file is fallback-only**, for environments where stdin piping is unavailable: `mkstemp`-equivalent mode 0600 (Windows: `%TEMP%`, per-user ACL), **unlinked immediately after read**, and a startup sweep of stale `lapis-batch-*.tmp` under `LAPIS_HOME`. Never `/tmp`-sticky-world-readable with prompt content.
- **The handler enforces its own caps** (max bytes + max entries per batch — don't rely on host chunking discipline). Drains are chunked ≤64KiB per dispatch.

### PR7b (M) — Training flywheel — fail-closed, ranking-only initially

`src/decision/train.js`: dataset builders (ranking first — the only surface with volume; capture accrues behind its audit path; staleness deferred — `purge_log` accrues).

**Segments and floors (v2.1 — fail-closed everywhere):**

1. **Three-way temporal session-boundary split, named `train / repair / gate` (70/15/15).** Fit on train; prior repair (global temperature + per-class bias offsets — 6–8 scalars) AND threshold derivation AND **early stopping (repair logloss)** on repair; the gate segment is **untouched** until the single gate run. Immature rows (pre-maturation) are dropped **before** splitting and n is re-derived — otherwise the newest 30% (val+gate) are exactly the immature rows. **Every segment has a floor** — including gate, which v2 left floorless: `val ≥ max(60, 0.15·n)` per segment; **minority floor is prevalence-aware: `n_train · p̂ ≥ 40`**, p̂ measured on the repair segment (v2's `0.1·n` encoded a 10% prevalence assumption; measured ranking prevalence is **1.0%** — it could never bind where it mattered). **Any segment below its floor → no gate, shadow only.** Fail-closed, in PR7b's text, not just Honest limits.
2. **Every gate declares α = 0.05 (two-sided), 80% power, and a min-n. The margin comes from the written cost ratio, not from MDE** — MDE is a **go/no-go precheck**: if MDE > margin at current n, the gate outcome is **"underpowered" = FAIL**. (An MDE-derived margin at thin n is a gate that cannot fail — worse than a theater gate.) Margins and analysis code are frozen per model version.
3. **Near-duplicate cross-boundary filter reuses the existing `DUPLICATE_DETECTION` stack** (MinHash-128 + LSH banding, 0.65 — constants.js) with an overlap-coefficient check for containment (trigram Jaccard is blind to embedding-restatement, this corpus's dominant dup shape). **Both copies are dropped from all supervised segments** (for a linear model the first-order leakage effect is correlated val rows narrowing CIs, not memorization); exclusion rate reported as a dataset stat; CIs use cluster-aware bootstrap.
4. **Ranking dataset builder first:** pairs from logged full candidate sets; labels from provenance-stamped matured outcomes; dedupe to last outcome per (memory, query, session). **Capture dataset builder (when capture reaches its audit path):** gold is **"escape from the current dream policy"** — NOT "durability". The dream rules key on the same variables the model consumes as features (phase 3 fires on the `Auto-detected` marker + recall counts + trust that are planned input features; 59% of historical deletions are `progress`-type phase-2 purges): a model trained on escape-from-rules re-learns the rules and calls it durability. The dataset build therefore **snapshots the dream phase set + constants versions** so label drift across dream-rule edits is detectable, and user `del`/`markDuplicate` enter as weak positive supervision at reduced weight.
5. **Capture veto gates are fail-closed with a human audit path.** The max-gain algebra is stated in the plan: a ≥80% retained-recall floor caps the veto budget at 20% of regex saves, so maximum achievable precision gain is +0.25p (+12.5pp at regex precision 0.5) — at the current ~272 all-time captures the gate MDE (~23pp) **exceeds the theoretical maximum gain**: the automated gate is jointly undecidable at reachable n (~2,300+ matured saves needed for a realistic vetoer; ~20k sessions at the measured 0.114 captures/session). Therefore: **until n_gate ≥ ~500 matured saves, capture promotion is decided by human audit of a sampled proposed-veto list (precision estimated with a binomial CI), never by the automated precision gate**; below min-n the automated gate returns "insufficient data" = FAIL, never pass-via-wide-margin.
6. **ε-exploration (only after capture reaches active mode, and only after sign-off):** arms are **randomized within ±w (w = 0.1) of the CURRENT fitted threshold t\*** — not a fixed-in-P window, which drifts off a threshold re-derived every cycle. Every arm row stamps `is_arm` + propensity; **calibration refit uses inverse-propensity weights** (unweighted arms bias the keep prior at the boundary); the retained-recall floor is computed **on non-arm decisions only** (both reported). **Arm rate defaults to 0** (`decision.explore_rate`); raising it requires the OQ2 sign-off, which is a **merge precondition for PR7b**. The ε rate + PRNG seed join the immutable version tuple (PR8).
7. **Retrain trigger:** durable `last_outcome_id` cursor per model on **matured** rows — ranking ~100 durable rank outcomes first; capture ~50 when its track activates. Idempotent across all dream entry points, never run-identity. `maybeRetrainDecisions` exported from `train.js` and INJECTED into compaction deps (no static cross-import; `FORBIDDEN_IMPORTS` gains 'decision' and reverse rules). Metrics computed by decision-evaluate/train only; dream never computes.
8. **Expected capacity stated up front:** a linear model whose zone features *are* the regex hits converges to "regex ensemble re-weighted by trust/recency" — expected discrimination AUC ≈ 0.6–0.75. A 0.65 shadow result is not failure; a 0.75 is not triumph.
