**Date:** 2026-09-21

**Deciders:** Gene Gulanes Jr.
**Supersedes:** v1 plan draft (3 internal review rounds)
**Related:** [`DREAM_CYCLE.md`](../DREAM_CYCLE.md), [`MODULE_MAP.md`](../MODULE_MAP.md), [`crosshash-strategy.md`](crosshash-strategy.md)

## Summary

A three-tier decision engine for LaPis's passive memory behaviors:

1. **Native JS engine** (`src/decision/`) — tiny linear models trained in-process on locally logged outcomes. **This is the critical path.**
2. **Existing regex classifiers** — day-0 behavior, unchanged, and the training baseline.
3. **Optional `laya-service/` Python sidecar** (pinned `laya` pkg, token-authed, `127.0.0.1:9110`) — a future third tier. Parallel and deferrable (PR9–PR11).

Everything lands **dark**: behavior is byte-identical until a model is explicitly promoted via `decision-promote`. The flywheel is PR-sliced (PR-1 … PR12) so every merged PR leaves `main` green and behaviorally dark.

**Semantics (unchanged from v1):** routing = FOUR `noul` questions (the four regex classifiers are non-exclusive, consumed at 4 separate call sites; `isPreflightWorthy` becomes `is_coding_task`); capture v0 = binary save/no-save (regex keeps assigning type; the model's first live role is **veto-only** — suppress false positives, never create saves); staleness = SQL rules generate candidates, model is a concordance veto (delete only if rule fired AND P(durable) < 0.30); ranking = λ-blend with the composite, never a hard gate; `decideScore` CUT (no ordinal surface exists).

- `purge_log(id INTEGER PRIMARY KEY AUTOINCREMENT, memory_id INTEGER — no FK, phase, reason, deleted_by, dream_run_id, created_at)`.
- `observation_versions.actor TEXT`.

THEN 'active' WHEN state='active' THEN 'retired' ELSE state END WHERE model_key=?`.
- `decision_log(id INTEGER PRIMARY KEY AUTOINCREMENT, model_key, dedupe_key, model_id INTEGER NULL, **memory_id INTEGER NULL**, acted_on INTEGER NOT NULL DEFAULT 1, backend, input_hash, state_format, features JSON, decision JSON, confidence, outcome, outcome_source, query_text, dream_run_id NULL, created_at)` — no cascading FKs. `memory_id` populated on capture (post-save) and rank rows at write time: outcome-closing and dataset joins get a real join column instead of dedupe-key string parsing. Unique dedupe via expression index + **targeted** conflict clause — *not* `INSERT OR IGNORE`, which silently swallows NOT NULL/CHECK violations:
  ```sql
  CREATE UNIQUE INDEX idx_decision_log_dedupe
    ON decision_log(dedupe_key, COALESCE(model_id, 0));
  -- inserts: ON CONFLICT (dedupe_key, COALESCE(model_id, 0)) DO NOTHING
  ```
  Additional indexes: `(model_key, id)` (cursor reads), `(created_at)` (retention), partial `(outcome) WHERE outcome IS NULL` (pending-outcome recovery). `features` stores a compact numeric vector (BLOB) or is dropped after `state` leaves `'shadow'` — `decision` JSON + `confidence` are the reproducibility-relevant parts. **90-day retention ships in this PR** (chunked deletes: `… WHERE id IN (SELECT … LIMIT 5000)` until `changes < 5000` — keeps WAL appends small), not in PR12.

Dedupe keys: `capture:<session>:<sha256(turnSeq || '\0' || text)>` (turn seq folded in — identical short texts within a session must not collide), `routing:<session>:<seq>`, `rank:<memory>:<sha256(query)>:<session>`, `stale:<dream_run_id>:<memory_id>`. **No `turnCount` in any key** — Pi increments it at `turn_end`'s top, CC increments before capture evaluation: off-by-one by construction.

**`dream_run_id` generation:** `dream()` stamps a run id **at entry** (increment `dream_run_count` at start, or `dream:<iso-ts>`), threaded through the deps already being extended in PR7a. Today the counter increments only at run end (`compaction.js:463-471`) — mid-loop purge/shadow rows would have no id.

**`last_outcome_id` cursor semantics:** per-model (`MAX(id) … WHERE model_key = ?` — table-global `MAX(id)` cross-contaminates concurrent shadow+active models), protected by AUTOINCREMENT (a plain `INTEGER PRIMARY KEY` restarts ids after any full-table cleanup, permanently stalling training), and updated monotonic: `SET last_outcome_id = MAX(last_outcome_id, :new)` — 4 dream entry points × 2 processes race; last-writer-wins would regress the cursor. Consider the existing `repo_index_locks` pattern as a dream lock.

Repository `src/platform/storage/repositories/decision.js` (facade over `data-access/decision.js`); **no `withTransaction`** (gateway path lacks it — and better-sqlite3's deferred `BEGIN` can raise unretryable `SQLITE_BUSY_SNAPSHOT` on read-then-write upgrades across processes, so the single-statement pattern is required, not just convenient). Update `test/storage-repositories.test.js` exact-key set (`'decision'` sorts between `codeIndex` and `docIndex`).

Tests: **real** V27-shape fixture (apply `schema.sql` with V28 objects removed, `user_version = 27`, `ensureDb()`, assert `origin` exists + backfill + `user_version = 28`) — the existing `db.test.js` migration test forces versions onto a final-shape DB and passes trivially; origin backfill; CRUD; schema-drift test (schema.sql ↔ MIGRATIONS).

### PR2a (M) — `src/decision/` pure core

- **`contract.js`** — laya wire format (`{state, questions:{qid:{type:'choice'|'noul', instructions, criteria?}}}` → `answers.{qid}` with probabilities/confidence); **four versioned state builders — the ONLY place truncation happens** so native and laya see identical bytes: `buildCaptureState` (head 300 + '…' + tail 700 + final line), `buildPromptState` (raw prompt serialized with the unified 500-char cap — **model-state only**: regex classifiers keep consuming raw text on both transports through day 0; unifying the classifier input is a behavior change and ships only as part of promotion), `buildMemoryPairState` (REQUEST + memory metadata + What/Why via existing `summarizeMemoryContent`), `buildStalenessState`; `state_format` int bumped on any builder change.
- **`features.js`** (pure) — tokenizer: NFKC, lowercase, camelCase/snake/kebab/path splitting (compound + parts), numbers→`<num>`, 40-char cap, CJK/Hangul/Kana runs → char bigrams; **signed hashing, 2^17 shared space** (2^18 only if the measured empirical collision rate over the real corpus justifies it — at n=200–1,000 rows the binding constraint is labels, not collisions); sublinear TF; zone features (existing regex hits as booleans); meta features with fixed transforms (trust clamp[0,1], counts log1p-capped, **age frozen at log time** (`age_at_event` stored on the row — a time-varying age breaks seeded determinism and is unidentifiable when train rows are uniformly old), `Number.isFinite` guards). The age feature is collinear with the composite's recency term (same 7d constant) — drop it or document the double-count under λ-blend.
- **`primitives.js`** (pure) — decideChoice (softmax), decideNoul (sigmoid), gate.
- **`evaluate.js`** — 5-bin equal-mass ECE + bootstrap CI (REPORT ONLY, never a gate), PR-AUC, MRR/nDCG.
- **Runtime compatibility rule:** a loaded model whose `feature_spec`/`state_format` ≠ current builders is **refused at score time** (treated as untrained) — silent feature skew is how this flywheel poisons its own shadow data. Dataset builders filter `decision_log` by current `state_format`.

Tests: determinism (seed hash excludes time-varying fields), pure functions, synthetic convergence.

### PR3 (S/M) — CLI router `src/cli/commands/decision.js`

Single-token commands: `decision-get-model` (returns `{models:{capture:null,…}, shadow:{…}, generated_at}` — nulls for untrained, NEVER errors), `decision-log-batch` (both unadvertised, dashboardRouter pattern), plus user-facing `decision-status/train/evaluate/promote/demote/log` (paginated, small payloads; no `_wrapAnalysis`). **Transport rules (v2):**

### PR4 (M) — Capture surface — instrumentation first

`shouldAutoCapture(text, model?)` in `pattern-matcher.js` (pure, weights-as-data — one edit serves the Pi re-export + `stop.js`; verified both import the same module).

Day-0 logging (unchanged intent, corrected mechanics): every gated evaluation logs with the acting tier (`backend='regex'`, `acted_on=1`, `model_id=NULL`); when a shadow model exists, additionally `acted_on=0` rows.

**v2 instrumentation corrections — the v1 dataset was invalid as supervision:**

1. **Label provenance:** every row carries `label_source ∈ {retrieval_stamp, consume, negative, purge}`. Today `insertRecallLog` maps `wasUseful === false ? 0 : 1` and `search()` writes `was_useful=1` for every returned row at retrieval time — 4,385 retrieval stamps vs 332 real negatives in the live DB. Retrieval stamps never train anything.
2. **Fix the dead negative producer:** `pendingRecallFeedback` is declared (`state.ts:128`), flushed, and **never populated anywhere**. Population site: at `turn_end`, injected memories not cited/anchored in the subsequent assistant text → `log-negative-recall`; cited ids → `consumeRecall`. Without this the ranking minority class never exists and the ≥40-minority gate is unreachable.
3. **Drain contract — dispatch-then-clear-on-success.** The pendingRecallFeedback pattern clears the queue *before* dispatch and ignores the result: daemon down, DB busy, or the 5s timeout → silent permanent loss during completely normal operation. Re-queue on null/throw; clear only on success; loss envelope = crash/kill only, bounded to one turn. Idempotent dedupe keys make the daemon→direct double-fire safe.
4. **Backstop drains:** `turn_end` does not fire on exit/abort. Add drains at Pi `session_shutdown` (`session-lifecycle.ts` already registers one) and CC `session-end.js`.
5. **Shared drain module in `src/hooks-engine/`** — the queue shape has already drifted between transports (Pi `Map<number, …>` vs CC `[]`; Pi stamps cooldown before dispatch/on failure, CC after success). Chunk, dispatch, re-queue-on-failure, clear-on-success: written once, imported by both.
6. **Rank rows never touch `recall_count` or `useful_ratio`** — `context.js:193-194` explicitly warns passive-injection logging poisons ranking; both SQL branches order by `recall_count DESC`. Separate table/column family. "Closing" a rank row is an UPDATE on `memory_id` + session (the existing `logNegativeRecall` is INSERT-only — there is no open row to close today).
7. **Queue entries carry their own identity:** (stable claude/payload session id, enqueue seq) — the numeric DB `sessionId` is reassigned on resume and falls back to `0` on session-start failure (which fail-open discards). Refuse to enqueue when the DB session id is 0/null; count the discards.
8. **Pi model refresh cadence:** per-turn in-process dispatch (~free) or a TTL mirroring `REPO_CACHE_TTL` (5min). Every model-influenced row stamps the weights digest it was scored under. CC per-hook re-read unchanged (caches deliberately excluded from state-store).
9. **90-day retention live from this PR** (moved from PR12).

Queues: Pi `pendingDecisionLogs` in `state.ts` drained at `turn_end` via `mem('decision-log-batch')` (added to `MAIN_THREAD_BLOCKING_COMMANDS`); CC `pendingDecisionLogs` in state-store defaults, drained under `mutate()` (fail-open under contention — documented; double-drain made safe by dedupe keys), dispatched outside the lock. CC loads the model via dispatch after cheap text gates, before the `mutate()` lock.

Tests: regex rows appear day 0 with `label_source`; no observation deltas; cooldown dedupe; queue survives a failed dispatch; size invariants.

### PR6 (M) — Ranking surface

`rankObservations(rows, query, model?)` + the post-query hook at `context.js:192` covering all selection paths converging there (baseline no-query path skips the model; within-CTE-top-N only). **λ-blend, not weight-init** (a linear model can't replicate the composite): min-max normalize both scorers WITHIN each candidate set; final = (1−λ)·composite + λ·learned; λ=0 shadow → 0.25 after promotion.

**v2 corrections:**
- **ε-guard on the blend:** degenerate sets are the norm, not the edge case — production injects are 1–3 memories (`PROMPT_INJECT_LIMIT=1`, `NAVIGATION_PROMPT_INJECT_LIMIT=2`), and all-tied scores make min-max 0/0. `range < 1e-9 → neutral 0.5`; candidate sets < 5 → λ=0 (composite only).
- **Log the FULL fetched candidate set with positions at query time.** The pool is 30 rows (`limit × SEARCH_MULTIPLIER=3`, capped `SEARCH_MAX_ROWS=50`) — v1 said "top-50"; and only the returned top-10 are logged anywhere today, so training pairs and honest MRR are unreconstructable without this.
- **Promotion gate replaced:** λ-doubling requires a single **pre-registered** paired sign test on pooled paired MRRs across cycles, with reported CI — v1's "p<0.1 across 3 consecutive cycles" passes with probability ≈ 0.3% even for a genuinely better ranker (and stale candidate sets correlate the per-cycle tests, invalidating the nominal error rate in both directions).
- **Auto-rollback owner specified:** a dream-time check adjacent to `maybeRetrainDecisions` (PR7b) performs the atomic demote on >10% MRR degradation. Nothing computed live MRR in v1.
- Optional dep threaded through `commands/search.js` + `memory.js` (absent key = off for preflight/http/todos). Ranking is native-only (no fixed option set → no laya choice mapping).

### PR7b (M) — Training flywheel

`src/decision/train.js`: dataset builders (capture binary from matured outcomes; ranking per PR6; staleness DEFERRED — purge_log accrues).

**v2 corrections — the v1 statistical layer could not do what it claimed:**

1. **Three-way temporal session-boundary split: 70/15/15** (fit / repair+threshold / untouched gate). v1 used one newest-20% segment as early-stop val, prior-repair fit set, Fβ threshold selector, AND gate holdout — every gate optimistically biased, at n≈60 by the same order as the effects under test.
2. **Per-surface floors, internally consistent:** `minority ≥ max(40, 0.1·n)`, `val ≥ max(60, 0.15·n)` — v1's `200 × 20% = 40 < 60` was unsatisfiable below 300 rows, and true minority prevalence differs by an order of magnitude across surfaces (ranking ≈1%, capture ≈10% all-time).
3. **MDE-derived margins:** each gate states its minimum detectable effect. v1's logloss +0.02 margin was ≈0.22 SE at n=60 (cannot distinguish +0.02 from +0.08); McNemar/sign at v1's floors had ~0–20% power.
4. **Capture gold = time-to-purge survival** (matured ≥14d past rule-eligibility), not consumed/ignored — passive injection (the dominant consumption path) deliberately refuses recall_log, so consumed/ignored is popularity-censored: the top-1,200 memories hold 97.1% of recall rows; never-surfaced → never-recalled → dream-purged → labeled non-durable.
5. **Veto gates fixed:** precision computed over a **non-empty retained set** (v1's degenerate optimum: veto everything → vacuous precision), plus a **retained-recall floor** (keep ≥80% of regex saves) so over-vetoing is penalized. The cost ratio is written down explicitly (lost-memory : retained-noise) and thresholds derived from it — v1's Fβ β=2 privileged keep-recall without stating the asymmetry, when a false veto silently destroys a true memory.
6. **ε-exploration on the veto boundary:** keep (don't veto) 5–10% of boundary cases P(save) ∈ [0.3, 0.5), logged as experiment arms. Veto-only otherwise has **no counterfactual gradient, ever** — capture is already 0.11/session and suppression pushes RETRAIN_MIN_NEW permanently out of reach.
7. **Retrain trigger:** durable `last_outcome_id` cursor per model on **matured** rows — capture ~50 (v1's 200 ≈ 1,800 future sessions at the measured capture rate; capture stays shadow-mode year one either way), ranking 1000. Idempotent across all dream entry points, never run-identity.
8. **Near-duplicate cross-boundary filter:** char-trigram Jaccard ≥ 0.7 (or simhash) — this corpus is *built* from restatement (session summaries, checkpoints) and sha256 can't see paraphrase; matches dropped from **train**, kept in val, leakage rate reported as a dataset stat.

## Honest limits (v2)

Day-0 behavior = regex (unchanged). **The sequencing verdict from the ML review stands: instrument (PR4/PR5/PR6/PR7a logging with provenance stamps and write-time feature snapshots) → re-define labels as matured, provenance-stamped outcomes → re-derive floors, thresholds, and MDEs from measured base rates → only then train.**

- **Ranking** plausibly clears a repaired gate in 6–12 months of real use (volume exists; labels are the constraint; safe only behind λ regardless).
- **Capture** stays shadow for year one: 272 auto-captures all-time, 0.11/session — not a dataset. The PR4 instrumentation is the load-bearing wall.
- **Routing** and **staleness** are instrumentation projects, not ML projects, until the PR4/PR5 logging lands (routing has zero persisted inputs today; staleness waits on purge_log + 3 dreams).
- Laya tier needs export → GPU fine-tune (adapting their notebook — no packaged API) → register → temperature refit → shadow-pass; base checkpoints are near-chance zero-shot AND overconfident as shipped (ECE 0.466). CPU latency is documented-plausible but unbenchmarked (PR10 exit criterion).
- Total ≈ **24–34 days**; native critical path **15–20**.

## Out of scope

No torch/Python in LaPis core; no auto-promotion (explicit CLI only); no automated GPU fine-tuning; no MCP tools; no dream counter race fix; `decideScore` and a staleness MODEL deferred (purge_log still ships); classifier-input unification (500-char) deferred to promotion, flagged as a behavior change.
